# 动态微信表情：流程总览

本页只回答“从用户输入到可交付 ZIP 怎么走”。细节分别见[整套执行](full-album-workflow.md)、[账号与费用](video-connections.md)、[输出与边缘质量](output-contract.md)。

## 先选入口

| 用户给的任务 | 路线 | 交付边界 |
|---|---|---|
| 做一套，8–24 张 | 独立视频整套：`album_workflow.py` | 同一主体锚图、逐张独立首帧与视频；按确认的透明底或保留背景模式检查全部 GIF，循环和文件大小合格后打包。 |
| 明确要先试若干张（常见 1–7 张） | 独立 1×1 样片任务 | 按试做意图交付指定样片；即使恰好有 8 张，也不自动升级为整套，不调用整套 `pack`。 |
| 用户给现成静图、九宫格或视频 | 相应的静图/网格/仅后处理入口 | 按实际素材和布局处理；九宫格单段视频不等于独立视频成套路线。 |

## 独立图生视频主线

1. **记录需求。** 记录主体描述或参考图、真人/虚构类型、指定风格、动作和确切数量；未指定整套动作时默认 8 张。主体锚图只确认主体，不要求场景图或背景模式答复。用户明确要场景则后续记录 `opaque`，明确要透明底才去背；无法判断时在主体确认后、生成动作首帧或视频前确定最终 GIF 的背景模式。保留参考人物可见特征，不自动加字。整套确定背景后运行 `album_workflow.py plan --background-mode ...`，形成编号、分组和调用预算；样片按实际数量建立独立任务，不伪装成 8 张计划。
2. **先过图像费用闸门，再只生一张主体图。** 在可能付费的主体图或静帧生成前，核对当前图像工具、账号权益、调用数和额外费用。费用未知或超过用户已同意范围就停在本地规划。对新的生成任务，只生成一张主体锚图，检查并展示实际图片，然后停止等待用户明确确认这张图；参考照不是已确认锚图。确认后写入图片哈希绑定的主体批准记录，才允许批量生成动作静帧或任何视频。只有恢复同一任务时才复用该任务已确认且哈希未变的主体图；新任务仍先生成一张。整套静帧默认每批最多 4 张，检测真实布局并裁成各自独立的 1×1 首帧。
3. **静帧质量与授权。** 核对主体相似度、风格、动作、肢体/道具完整性和真实 Alpha，保存首帧与计划/图片哈希。用户要求先看图时，展示静帧并等待其确认；用户明确要求直接完成时，可在静帧通过检查后用 `generated-direct`（样片）或绑定专辑计划与编号的 `album-generated`（整套）记录授权，不逐张追问。图片变化使原状态失效。
4. **只读发现并选择视频模型。** 分开核对“已安装/已登录、视频权限、真人素材资格、额度/费用”；登录缓存本身不代表可生成。保存用户选定的 Grok、MiniMax H3、Wan 3.0 或合格的 Seedance 连接；API Key 仅由用户在交互终端输入并进入系统凭据库。真人 Seedance 另需平台肖像资产资格。未明确选择时按路由规则推荐，选定后不自动换模型。
5. **逐任务准备与总预检。** 为每张静帧建立独立 `video/NN`、1×1 布局、动作提示、模型任务、路由和单次费用确认。整套先执行 `album_workflow.py preflight` 核对所有图片/任务/授权，再按用户已同意的整套费用上限 `authorize-batch`。确认有效期一小时；过期先重新核对账号和额度。样片只核对各自的单次任务与费用确认。
6. **顺序生成视频。** 外部适配器整套由 `album_workflow.py run` 逐张执行；Agent 原生视频路线由 Agent 顺序调用并逐张登记。每张仅一次提交并记录任务 ID、结果和失败原因。失败暂停后续可能付费的调用；已提交但结果未知时只查询原任务，不盲目再提交；新尝试或换模型重新核对费用与授权。当前 Grok 适配器只支持纯色色键透明路线；绿色主体先选高反差色键；场景可来自首帧，也可由支持该能力的视频模型按提示词生成，不能悄悄去背。
7. **本地转 GIF 与人工审片。** 对每段视频核对主体稳定、动作和背景模式。透明底视频才做色键 QC、抠图与 Alpha/GIF 边缘检查；保留场景的视频用 `scene_video_to_gif.py` 直接转 240×240 循环 GIF，不跑去背景处理。最终 GIF 均检查首尾跳帧、边缘质量和大小。`pack` 按计划验收透明或不透明，拒绝同套混用。任何本地重导都不需要再调用视频模型。
8. **制作附加素材并交付。** 全部 GIF 达标后，按 [附加素材与打包](album-submission-assets.md) 分别制作详情页横幅、表情封面、聊天页图标和默认成对的赞赏图；新增图像模型费用先核对。使用本 Skill 的 `album_assets.py` 处理与验证，再用 `album_workflow.py pack --asset-dir ...` 将动态 GIF 改为独特的 1–4 字中文主题名，连同附加素材一同装入中文命名 ZIP。缺素材、尺寸/透明度/格式不合格或 GIF 数量不符时拒绝打包。还要人工确认主体一致、动作各不相同、无非预期文字、留白合理；文件检查不等于微信平台审核，正式上传以当前页面要求为准。

“一键”是用户给出任务且确认生成的主体图后，在已核对的费用和授权范围内连续编排后续步骤；它不跳过主体图确认、生成成本、静帧质量、失败处理或最终人工审片。当前两张足球样片验证了 Grok → 视频 → GIF 的样片链路，不代表 8–24 张整套曾以真实账号全程跑通；其他模型的本地适配器与实际账号权限也要分开判断。
