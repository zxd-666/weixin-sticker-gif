# Images 2.6 直出 GIF 优先路线

此路线用于**新生成**的单张样片和整套表情。保留已有的主体锚图确认、背景模式、费用边界及最终 GIF 验收。收到现成 GIF 时只做后处理与验收。`album_workflow.py plan` 的新清单把 `gpt-image-2.6-gif` 设为优先路线；`video/NN` 是按需回退工作区，不表示先生成视频。旧版独立视频计划仍可读取。

## 调用前

1. 在确认主体锚图后，核对当前 Agent 是否有**显式**可调用的 Images 2.6 GIF 能力：准确的模型 ID、GIF 输出格式、下载原始文件、额度/费用。普通生图工具即使提示词写“GIF”，若接口没有 GIF 参数、实际返回 PNG，就不算直出。
2. 可用原生工具时优先在当前 Agent 调用；有已配置且可用的 OpenAI Image API 时，使用 `scripts/generate_image_gif.py`；两者都不可用但已登录的 ChatGPT GIF 创作界面可用时，可经界面逐张生成并下载原始 GIF，记录为 `chatgpt-gif-ui`。界面路线可用于真实交付，但没有可核对的请求模型 ID 时不得写成“已直接调用 `gpt-image-2.6-sunburst` API”。API 脚本只走 `POST /v1/images/generations` 的文本生 GIF，默认 `gpt-image-2.6-sunburst`、9 帧、每帧 200 ms、`size=auto`、`quality=medium`。API 的 GIF 编辑接口暂不可用，因此不能声称把已确认锚图作为该 API 请求的像素参考；要从锚图提取可见身份特征写入提示词，并逐张审查一致性。若原生工具或 ChatGPT 界面支持参考图生 GIF，可传入原锚图并记录真实输入能力。
3. 调用前核对所选工具或界面的账号权限、价格、预计次数和整套费用上限。API 脚本要求 `OPENAI_API_KEY` 在当前进程中可用，并要求 `--cost-confirmed`；密钥不得出现在提示词、清单或日志。账号缺少 GIF 权限、费用未知或用户预算不覆盖时，不提交请求；转去已授权且可用的备用路线。`--cost-confirmed` 只能在用户已确认相应费用后使用，不是自动授权。每张最多提交一次；失败或换模型、重试先重新核对费用。

## 提示词与画面

每张只描述**一个聊天表情动作**，固定镜头、角色造型和色彩。角色身份沿用已确认锚图；主题名仅写入文件与清单，画面默认无文字。先写起始姿势、动作中段、回到起始姿势的结尾，要求首尾角色位置、表情、道具和背景状态接近，构成自然循环。9 帧约 1.8 秒可作为起点，动作时长按实际画面调整。

有背景时，背景只放支持情绪和场景识别的少量**静态**元素，保持同一构图与光线。不要自行增加车辆、路人、飞行物、持续下落/飘动的粒子、滚动文字或不停变换的灯光；这些元素会让末帧回首帧时突然跳位。用户明确指定的动态元素应保留，但必须设计可回到起点的运动，否则先说明该动作更适合视频路线。雨夜可以保留路灯和站牌，不要自动添一辆从远处开近的公交车。减少细碎纹理也有利于控制 GIF 体积，但不能删除用户指定的关键场景。

提示词骨架：

> 以已确认角色的可见身份特征为准：[具体脸/毛色/服装/比例]。240 像素下仍清楚的单一主体，固定方形镜头。[一个简洁场景与少量静态背景元素]，背景在所有帧位置和亮度保持不变，无额外移动物体，无文字。动作序列：[起始姿势] → [清楚的表情/肢体动作] → [回到与首帧接近的姿势]。首尾角色位置、表情、背景一致，适合无限循环。输出真正的多帧 GIF，不要静图、视频或分格帧图。

背景模式为 `transparent` 时，只有所选工具能**实际输出**具有透明像素的 GIF、且逐帧验收通过，才走直出；不要把“支持透明 PNG”和“支持透明 GIF”混为一谈。否则使用原有透明底视频/色键路线。`opaque` 模式不得擅自去背、换绿幕或铺白底。

## 本地处理与验收

原生工具或 API 返回的原始 GIF 保存在 `gif/NN/source.gif`，同时记录模型/工具 ID、提示词、输入参考能力、原始文件哈希、费用与请求收据。API 脚本默认在旁边生成 `source.receipt.json`，包含返回的用量但不包含密钥。可用 API 时，示例命令：

```bash
python3 scripts/generate_image_gif.py --prompt-file works/角色/gif/01/prompt.txt --output works/角色/gif/01/source.gif --model gpt-image-2.6-sunburst --cost-confirmed
python3 scripts/direct_gif_to_sticker.py works/角色/gif/01/source.gif works/角色/final-gifs/01.gif --background-mode opaque
```

第二步只在本地缩放和压缩，或复制已经合格的 GIF；不调用视频模型。`opaque` 模式下会拒绝原始 GIF 的实际透明像素；`transparent` 模式下只接受已经满足微信规格的真正透明 GIF，避免压缩时悄悄铺底。输出仍由 `album_workflow.py pack` 按 240×240、≤500000 字节、无限循环、动态帧和整套背景模式验收。

**循环质量必须看最终 GIF。** 在实际 240×240 尺寸及九帧预览里检查起始、峰值、结尾，特别看角色是否回位、背景/道具是否瞬移、压缩后是否闪烁；机器的无限循环标记不证明视觉无缝。若只是尺寸或体积问题，先本地重导；若背景或动作不闭合，收紧提示词后仅对该张按费用边界重生。重新生成仍不合格、角色身份漂移或动作需要持续场景运动时，转原有逐张视频路线；不得自动对整套重复付费，也不得把不合格 GIF 塞入成品。直出合格项与视频回退合格项可在**相同背景模式**的计划下共同打包，逐张保留来源。
