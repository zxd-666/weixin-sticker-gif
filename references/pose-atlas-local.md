# 透明姿态图集 → 本地 GIF

适用于用户看重图像／视频调用次数、直出 GIF 身份或透明度不稳定，且动作能用少量清楚的关键姿态表达时。Brave 三张样片验证了单图轻动效、四格挥手和九格跃起可以在不调用视频模型的情况下输出合规 GIF；四格挥手仍有姿态切换跳感，九格跃起的鬃毛／披风有逐帧变化。样片没有金额收据，不能据此承诺现金节省或通用画质。

## 选路与费用

- 新任务仍先生成、展示并确认**一张主体锚图**，用 `subject_anchor.py` 保存确认记录。确认前不得生成动作图集。用户提供的旧参考照不是本任务的已确认锚图。
- 仅支持 `transparent` 成品。明确要原场景或有底色时走直出 GIF／视频路线，不自动抠掉场景。
- 整套若选择图集路线，用 `album_workflow.py plan --generation-mode pose-atlas-local --background-mode transparent`。预算按每张**最多一张**姿态图集估算；轻动效复用已有图像，不增加图像调用。先核对图像工具的权限、价格、计划数量和费用上限，再逐张生成、检查和记录真实调用。图集失败、换模型或重试不能自动追加计费。
- 简单点头、轻弹、摇摆可只用已确认的单张主体图，标为 `light-local`；整套里每张仍需有不同的可见表情或姿态，不能把同一锚图配不同文件名当成一套。挥手、鞠躬、跃起等改变肢体姿态的动作需要 `atlas-local`。复杂连续动作、镜头变化、身份一致性要求很高而图集不稳定时，按已核对费用改走独立视频；若改用直出 GIF，先重建计划并重新核对调用上限，不把整体形变说成肢体动画。

## 生成图集

每张表情使用一张独立的 2×2、3×3 或 4×4 正方形图集，格子按从左到右、从上到下编号 `0…N-1`。同一图集只画**同一个动作的连续姿态**，不是 N 个不同表情。以已确认锚图作为图像参考，固定镜头、角色身份、比例和服装；留透明格间距，保持共同脚底基线与角色位置。起势、动作峰值、收势要能回到起点。画面默认无文字，主题名只用于文件与清单。

检查图集实际格数、顺序、人物细节、手脚和鬃毛有无截断，确认是**真实 Alpha**，而非棋盘格或纯白底。某格失败只重做受影响图集，并在新增付费调用前复核预算。稀疏姿态可以本地重排；默认拒绝相邻重复帧，避免无意停顿。蓄力、跃起峰值或落地需要短暂停留时才显式加 `--allow-holds`，收据会记录停留位置；循环首尾仍不得重复。脚本不会凭静止图补出手臂动作，也不做光流插帧。

## 导出与验收

图集和锚图确认记录已就绪后，按实际姿态编排 `--order`；这里的顺序只是示例，须逐格审查后确定：

```bash
python3 scripts/pose_atlas_local.py --mode atlas \
  --source works/角色/atlas/02.png --grid 2 --order 0,1,2,3,2,1 \
  --anchor-approval works/角色/subject-anchor-approval.json \
  --output works/角色/final-gifs/02.gif

python3 scripts/pose_atlas_local.py --mode light \
  --source works/角色/subject-anchor.png \
  --anchor-approval works/角色/subject-anchor-approval.json \
  --output works/角色/final-gifs/01.gif
```

脚本使用统一裁格与缩放，保留姿态相对位置；轻弹使用连续移动的短循环。它拒绝不透明输入、相邻或首尾完全重复的帧、尺寸／透明／循环／500000 字节不合格的成品，并在同目录写 `.receipt.json`，记录输入和锚图哈希、帧序与警告。输出路径已有文件时拒绝覆盖。图集接近格边界会警告，须人工判断是否裁切。

在最终 240×240 GIF 上看完整循环、首尾接缝、人物脸和配饰稳定性、鬃毛与披风闪烁、透明边缘以及小屏动作可辨性。机器通过只能证明文件规格，不能证明动作自然。合格项可与同为透明底的其他路线产物一起放入 `final-gifs/NN.gif`，按原有附加素材及 `album_workflow.py pack` 打包。单张或少量样片直接交付 GIF 与收据，不冒充整套微信表情专辑。
